# auto_choice

给三个条件，随机替你决定今天吃哪儿。

**在线使用：** https://calcury.github.io/auto_choice/

纯静态页面，无框架、无构建、无后端。手写 CSS 与原生 JS，数据存在浏览器本地。

## 输入

| 条件 | 范围 | 默认 |
| --- | --- | --- |
| 可用时间 | 10 分钟 – 3 小时，步长 5 分钟 | 1 小时 30 分 |
| 口味 | 清淡 ←→ 重口 | 中间 |
| 人数 | 1 – 9 | 5 |

## 规则

每家店记录四个属性：名称、耗时区间、口味值（0 清淡 – 1 重口）、建议人数上限。
页面上每家店显示的都是**当前时点的预计耗时**，一个确定的数字，不再是区间。

### 时间：先算一个数，再卡死

```
预计耗时 = 区间中点 + (区间上限 − 区间中点) × 饭点强度
```

- 非饭点 → 区间中点。`30–60 分` 算 **45 分**
- 饭点峰值（12:15 / 18:00）→ 直接按上限。`30–60 分` 算 **60 分**
- 中间时刻按三角波插值，11:52 这种时候落在两者之间
- **周末**：上限先压到区间中点（`1–2h → 1–1.5h`），再套上面的公式 → 45 分变 37.5 分

然后是一道硬门槛：

```
可用时间 = 你输入的时间 − 5 分钟（缓冲）
预计耗时 < 可用时间        ← 严格小于，刚好卡点不算
```

不够就出局，没有"勉强能去"。一家都不够时，页面会直接告诉你最快那家还差几分钟、要把时间调到多少。

### 口味

用的是口味刻度上的绝对差值，不是钟形分布。

- 比用户**清淡**的方向几乎不罚（最多降 15%）——选重口的人吃清淡的完全没问题，清淡选项照样进池子。
- 比用户**重口**的方向走 sigmoid：差值 0.3 以内是平台期，过了中点急剧下掉。
  所以选「不挑」不会让「不挑」的店概率更高，而是让 0.85 以上的店掉得很快。

### 人数

超出建议上限后，每多一人权重乘 0.42。超太多自然出局。

另外，「换一个」会把当前这家临时压到 1/20；如果它是唯一来得及的店，还是会给它。

## 数据

默认清单在 [`data/restaurants.json`](data/restaurants.json)。

```json
{
  "restaurants": [
    {
      "id": "noodle-wang",
      "name": "老王牛肉面",
      "minMinutes": 30,
      "maxMinutes": 60,
      "taste": 0.55,
      "maxPeople": 6,
      "note": "汤头浓，出餐稳定"
    }
  ]
}
```

`minMinutes` / `maxMinutes` 单位是分钟，`taste` 0–1，`maxPeople` 是建议人数上限。
改完推送，页面里点「从仓库重载」即可生效。

页面上加的店自动存 `localStorage`，并且**不会**被「从仓库重载」冲掉；导出的 JSON 可以直接替换仓库里那个文件。

## 本地跑

```bash
python -m http.server 8000
# 打开 http://localhost:8000
```

直接双击 `index.html` 也能用，只是读不到仓库 JSON，会退回内置清单。
